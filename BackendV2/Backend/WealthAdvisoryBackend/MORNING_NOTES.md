# Morning Notes — Backend Documentation

## Overview

Scheduled, configurable morning notes for wealth advisors. Notes are generated by an AI agent, stored in AWS, and served instantly on page load.

**Stack:** FastAPI · APScheduler · DynamoDB · S3 · StockStory (Gemini 2.5 Pro) · Perplexity MCP

---

## AWS Resources

| Resource | Name | Purpose |
|---|---|---|
| DynamoDB | `WA_MorningNotesConfig` | Advisor config (PK: `advisor_id`) |
| DynamoDB | `WA_MorningNotes` | Note metadata per day (PK: `advisor_id`, SK: `date`) |
| S3 | `wa-morning-notes-store` | Note markdown files |

**S3 key structure:** `{advisor_id}/{YYYY}/{MM}/{YYYY-MM-DD}.md`

**DynamoDB TTL:** Notes auto-expire after 1 year via `ttl` attribute.

## Startup Sequence

```
api_v2.py starts
  ├── boto3 connects → DynamoDB + S3
  ├── APScheduler starts
  └── reads WA_MorningNotesConfig → schedules job
        └── fallback: DEFAULT_MORNING_NOTE_CONFIG (06:30 EST, Mon-Fri)
```

---

## Config Flow

```
POST /api/morning-notes/config  { sectors, tone, schedule, ... }
  ├── merge with DEFAULT_MORNING_NOTE_CONFIG (safe partial save)
  ├── write → WA_MorningNotesConfig (DynamoDB)
  ├── write → data/morning_notes_config.json  (local fallback)
  └── reschedule APScheduler job
```

**Config read priority:**
```
DynamoDB → local JSON file → DEFAULT_MORNING_NOTE_CONFIG
```

---

## Note Generation Flow

Triggered by scheduler or `POST /api/morning-notes`.

```
1. Read config from WA_MorningNotesConfig
2. Write { status: "generating" } → WA_MorningNotes
3. Build prompt from config
      sectors   → "Focus ONLY on: Macro, Equities..."
      tone      → "bullet points only, under 400 words"
      sections  → "SKIP Trade Ideas entirely"
      opinion   → "provide moderate views"
4. POST :7000/process_message
      └── Gemini 2.5 Pro
            └── Perplexity MCP → sonar-pro (live web search)
5. Strip completeness checklist from output
6. PUT markdown → S3  (key: default/YYYY/MM/date.md)
7. Write metadata → WA_MorningNotes
      { status, s3_key, word_count, topics_covered,
        config_snapshot, trigger, ttl }
```

---

## Page Load Flow (Frontend)

```
GET /api/morning-notes/today
  ├── completed  → fetch .md from S3 → return to frontend
  ├── generating │
  ├── failed     ├── GET /api/morning-notes/date/yesterday
  └── not_found  │     ├── found  → return with isStale=true
                 │     └── not found → trigger fresh generation
                 └── POST /api/morning-notes
```

---

## Fallback Chain

```
DynamoDB down     → local JSON file
Local file missing → DEFAULT_MORNING_NOTE_CONFIG
S3 down           → local .md file
Today missing     → yesterday's note  ("Yesterday" badge in UI)
Yesterday missing → HARDCODED_SECTIONS (UI never empty)
Generation fails  → HARDCODED_SECTIONS
```

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/morning-notes/today` | Today's note from DynamoDB + S3 |
| `GET` | `/api/morning-notes/date/{date}` | Specific date's note |
| `POST` | `/api/morning-notes` | Generate fresh note |
| `DELETE` | `/api/morning-notes/today/reset` | Clear today before regeneration |
| `GET` | `/api/morning-notes/config` | Read advisor config |
| `POST` | `/api/morning-notes/config` | Save config + reschedule |
| `GET` | `/api/morning-notes/history` | Last N notes metadata |
| `GET` | `/api/morning-notes/scheduler/status` | APScheduler job state |

| File | Role |
|---|---|
