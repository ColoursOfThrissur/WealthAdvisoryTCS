1. COCKPIT PAGE  (/  — activeTab: 'cockpit')
================================================================================

COMPONENTS:
  PriorityQueue        — Left column. Client list + detail panel
  MeetingIntelligence  — Right column top. Calendar + meeting prep card
  PortfolioMonitor     — Right column bottom. Action item counts
  MorningNoteBanner    — Top bar. News pills + market event pill

--- PriorityQueue ---
Features:
  - Ranked client list (6 clients) with priority pills (Critical/High/Medium)
  - Left-border color coding per priority
  - Click to expand right detail panel
  - Detail panel: avatar, metrics row (AUM/Return/Risk/Credit/Age), trigger reason, recommended actions
  - Actions navigate to rebalancing / meeting prep / proposals

HARDCODED:
  - All 6 client profiles built from worklistCustomers.json + 4 manually hardcoded (Sam Pai, Kevin Smyth, Sarah Jenkins, David Thompson)

  - "AI-ranked clients" label is misleading — it is not AI ranked

NEEDS BACKEND:

--- MeetingIntelligence ---

2. ASSIST PAGE  (/  — activeTab: 'advisor-assist')
================================================================================

COMPONENT: BackendChatInterface

Features:
  - 4 mode chips: Draft Email, Meeting Prep, Research Sector, Generate Client Report
  - Mode-specific color theming (purple=meeting, indigo=research, green=report, blue=email)
  - Welcome screen with suggested prompts per mode
  - Scroll buttons (up/down) when messages overflow
  - AgentTrace spinner with phase labels during processing
  - Google auth overlay (popup + polling) for meeting prep 401s

--- Normal / Report / Email modes ---
  - WebSocket connection to main backend (port 8001)
  - Session persisted in localStorage (report_session_id)
  - Streams status messages → AgentTrace
  - Renders SectionResult cards for structured report data
  - Report mode: generates client portfolio reports via orchestrator

HARDCODED:
  - Quick actions for each mode are static strings
  - Email mode sends to WebSocket but no actual email drafting backend exists
  - Suggested prompts reference hardcoded client names (Sarah Mitchell, David Chen, Robert Anderson)

--- Research mode ---
  - Direct HTTP POST to /api/research/{sessionId} on main backend
  - Forwards to StockStory server (port 7000) with session memory (last 5 messages)
  - Renders formatted markdown response with tables, headings, lists
  - Indigo color accent

HARDCODED:
  - Research suggested prompts (AAPL, Large cap tech, Renewable energy) are static

--- Meeting Prep mode ---
  - Direct HTTP POST to MEETING_PREP_API_URL/client-prep
  - Sends { user_id: logged-in email, client_name: query }
  - AgentCore backend finds calendar event, runs 5-agent pipeline, returns structured JSON
  - formatMeetingData() converts meetings[0] to markdown
  - Renders with purple .meeting-response styling
  - Auth overlay on 401 with popup + polling

HARDCODED:
  - Suggested prompts (Mary Hargrave, Sam Pai) are static names
  - user_id falls back to 'my-test-user' if not logged in

NEEDS BACKEND:
  - Email drafting backend for email mode
  - Meeting prep suggested prompts should come from today's actual calendar

================================================================================
UI ASSESSMENT
================================================================================

--- WHAT WORKS WELL ---

1. Dark theme palette — the deep green-black (#050807 → #0a1a14) is distinctive and professional.
   The success green (#10b981) as the primary accent creates strong visual hierarchy.

2. Mode-based color theming in Assist — purple/indigo/green/blue per mode is a smart pattern.
   The CSS variable --mode-color cascading to input focus, send button, user bubble is elegant.

3. MeetingPrep page layout — the 3-row 2-column grid is well structured. Cards have clear
   hierarchy (icon + title + AI badge). Scroll fade on overflow cards is a nice touch.

4. AgentTrace component — the single-line spinner with phase labels and elapsed timer is clean
   and informative without being noisy.

5. Priority Queue split layout — list + detail panel side by side works well for the use case.
   Left-border color coding for priority is immediately readable.

6. Morning Notes banner — horizontal scrollable pills with hover dropdowns is space-efficient.
   The long-press refresh to reset mailer state is a clever hidden gesture.

7. Meeting Intelligence card — the static + live merge with time sorting is clean.
   Progress bar with phase labels during generation is informative.

8. Auth overlay — reusing ov-auth-card / ov-auth-overlay across Overview and Assist is consistent.

--- UI ISSUES ---

1. CARD CONTRAST — Cards (bg-secondary #0a1a14) sit on a background gradient that passes through
   the same color. Cards are nearly invisible without hover. No glassmorphism works here because
   the background has no visual depth to blur through.
   FIX IDEA: Add a very subtle top border highlight (1px rgba(255,255,255,0.06)) and slightly
   increase shadow depth. Or use a background image/noise texture on body to give blur something
   to work with.

2. PORTFOLIO MONITOR — All counts are fake (12, 8, 3, 5, 1, 12). The "AI" badge is misleading.
   4 of 6 items have no destination. This card actively misleads users in a demo context.
   FIX: Either connect to real data or clearly label as "Coming Soon" for unconnected items.

3. MASS MAILER — Email sending is completely simulated. The "✓ Emails sent successfully" message
   is fake. In a demo this is fine but needs a clear disclaimer or visual indicator that it's a
   simulation. The completion summary says "Follow-up tasks created in CRM" which is also fake.

4. PRIORITY QUEUE — "AI-ranked clients" label is inaccurate. The ranking is manual/hardcoded.
   The "Why this client is prioritised" text is template-generated, not AI reasoning.
   FIX: Either connect real AI scoring or change label to "Priority Clients" without the AI claim.

5. ENGAGEMENT BAR in worklists — The formula (age + contribution) / 2 produces arbitrary numbers
   that have no real meaning. A 28-year-old with high contribution scores higher than a 58-year-old
   with medium contribution — this is not engagement, it's age bias.
   FIX: Remove or replace with a real metric (last interaction date, response rate, etc.)

6. PROPOSALS WORKLIST — Time badges are hash-based fake timestamps. Sam Pai "3d" is hardcoded
   by name. Priority labels differ from Rebalancing worklist (High vs Critical, On Track vs Medium).
   FIX: Consistent priority labelling across all worklists.

7. MEETING PREP — Mary Hargrave, Jean Williams, Marcus Thompson fall back to Alex Morgan's data.
   If you navigate to /meeting-prep/15634602 you see Alex Morgan's holdings and risks with
   Mary Hargrave's name in the header. This is a data integrity issue.
   FIX: Add proper static data for Mary Hargrave at minimum (she appears in multiple flows).

8. ASSIST PAGE — Meeting prep placeholder text says "What meeting prep do you need?" but the
   mode actually calls /client-prep which requires a specific client name. Users may type
   questions instead of names and get confusing results.
   FIX: Placeholder should say "Enter a client name (e.g. David Thompson)"

9. LIVE MEETING tab — activeTab: 'meeting-assist' shows a "Coming soon" placeholder. The tab
   exists in the nav but leads nowhere. This creates a dead end in the navigation.
   FIX: Either remove the tab or add a meaningful placeholder with roadmap context.

10. MASS MAILER OVERLAY — position: fixed with top: 132px assumes header (70px) + banner (62px)
    is always exactly 132px. If the banner is loading or absent, the overlay has a gap at the top.
    FIX: Use a CSS variable or JS measurement for the offset rather than a hardcoded pixel value.

11. TICKER in header — S&P 500 (5,308 +0.02%), AUM ($6.2M +0.05%), Clients (250) are all
    hardcoded static values. In a demo this is fine but they never update.
    FIX: Connect S&P to a market data API, AUM to portfolio sum, Clients to actual count.

12. REPORT MODE in Assist — The WebSocket backend generates PDF reports but the UI shows
    section cards inline. The download link works but the inline rendering of large reports
    can overflow the chat area with no pagination or collapsing.
    FIX: Add collapsible sections or a "View Full Report" button that opens in a new view.

--- IMPROVEMENT IDEAS ---

1. MEETING PREP CHAT — The formatMeetingData() markdown output is good but long. Consider
   adding a collapsible section per category (Holdings, Risks, Activity etc.) so the user
   can scan quickly and expand what they need.

2. PRIORITY QUEUE — Add a "last contacted" indicator on each client row. Even a simple
   "3d ago" badge would make the list feel more actionable and real.

3. MORNING NOTES — The pill row only shows one section before the market event pill.
   Consider showing 2-3 pills before the event pill so the banner feels richer.

4. MEETING INTELLIGENCE — When Google Calendar is connected and has events, the static
   Alex Morgan / Kevin Smyth rows blend in with live events. A subtle visual differentiator
   (e.g. a small "Static" or "Pre-loaded" label, or a slightly different left border color)
   would help distinguish them.

5. ASSIST PAGE — Research and Meeting Prep both use localMessages (separate from WebSocket
   chatMessages). Switching modes clears the visible messages but they're still in state.
   A "Clear conversation" button per mode would be useful.

6. PPTX EXPORT — Currently only works for live AgentCore results. Adding PPTX generation
   for static clients (C005, C012, Alex Morgan) would make the demo more complete since
   those are the most polished briefs.

7. WORKLIST TABLES — Both worklists use plain HTML tables with custom CSS. Consider adding
   row-level expand to show the trigger/key context inline without navigating away.
   This would reduce navigation friction for quick triage.
